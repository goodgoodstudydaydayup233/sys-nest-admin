# java-server 知识点说明

> 这份文档用大白话记录 `java-server`（Spring Boot 版后台）现在用到的技术点，并尽量和 `node-server`（NestJS 版）对照着讲：**“这个在 Nest 里相当于什么”**。
> 文档会跟着功能一起更新，每次新增内容请补到文末「更新记录」。
>
> 当前版本：**v0.16（端口统一）** · 更新日期：2026-11-22

---

## 0. 先建立整体印象（看这一节就够入门）

同样一个后台，NestJS 和 Spring Boot 只是“说法”不同，做的事情是一一对应的：

| Spring Boot 的说法           | 大白话解释                                            | NestJS 里的对应物                  |
| ---------------------------- | ----------------------------------------------------- | ---------------------------------- |
| 注解（`@RestController`）  | 贴在类/方法上的“标签”，框架看到标签就帮你干对应的活 | 装饰器（`@Controller()`）        |
| Bean                         | 交给 Spring 创建和管理的对象                          | Provider（`@Injectable()` 的类） |
| 依赖注入                     | 构造函数里写要什么，Spring 自动把对象塞给你           | 构造函数注入                       |
| starter                      | 一个“全家桶依赖”，引进来就带好相关配置              | 一个封装好的 Module                |
| 自动配置                     | 根据你引的包，自动决定要创建哪些 Bean                 | `imports: [...]` 引入模块        |
| `application.yml`          | 配置文件                                              | `config/development.yml`         |
| profile                      | 开发/生产环境切换开关                                 | `NODE_ENV` + 不同配置文件        |
| `@ConfigurationProperties` | 把 yml 里的配置映射成一个 Java 对象                   | `ConfigService` 读取配置         |
| `@RestControllerAdvice`    | 全局统一处理异常                                      | 全局 ExceptionFilter               |
| `Filter` / `Interceptor` | 请求进入业务代码前的一道道关卡                        | Guard / Middleware / Interceptor   |
| `BaseMapper<T>`            | 自带增删改查的数据库操作接口                          | Repository + TypeORM               |
| `SseEmitter`               | 服务端往浏览器持续推消息                              | SSE（`message-sse.service`）     |

后面的每一节都会在关键位置再补一句“相当于 Nest 的 xxx”，方便随时对照。

| Java 目录      | 放什么                         | Nest 对应                |
| -------------- | ------------------------------ | ------------------------ |
| `controller` | 接请求、校参数、返回结果       | `*.controller.ts`      |

> 一句话记忆：**Java 的包名 = Nest 的文件名后缀**，只是 Java 用目录分层。

## 3. Spring Boot 基础

### 3.1 启动类：整个程序的大门

文件：[SysNestAdminApplication.java](src/main/java/com/sysnest/admin/SysNestAdminApplication.java)

```java
@SpringBootApplication(exclude = UserDetailsServiceAutoConfiguration.class)
@ConfigurationPropertiesScan
@MapperScan("com.sysnest.admin.modules.**.mapper")
public class SysNestAdminApplication {
    public static void main(String[] args) {
        SpringApplication.run(SysNestAdminApplication.class, args);
    }
}
```

用大白话说：

- `main` 方法一跑，Spring 就把整个应用“点着”了，相当于执行 `nest start`。
- `@SpringBootApplication` 是三个功能的合体：
  - `@Configuration`：这个类可以定义 Bean（可以理解为“可以往外提供对象”）；
  - `@EnableAutoConfiguration`：自动配置，引了什么包就自动准备好什么（相当于 Nest 里 import 一堆 Module）；
  - `@ComponentScan`：自动扫描当前包及子包下所有带 `@Component`/`@Service`/`@RestController` 等标签的类，注册成 Bean。
- `exclude = UserDetailsServiceAutoConfiguration.class`：Spring Security 默认会塞一个内存用户并打印随机密码。我们用 JWT，不需要它，所以关掉。
- `@ConfigurationPropertiesScan`：自动扫描 `@ConfigurationProperties` 配置类，不用一个个手动注册。
- `@MapperScan("com.sysnest.admin.modules.**.mapper")`：告诉 MyBatis“`modules` 下所有 `mapper` 包里的接口都是数据库操作接口”，相当于 Nest 里每个模块 `TypeOrmModule.forFeature([...])` 的批量版。

> Nest 对照：`main.ts` 负责启动和全局配置，`app.module.ts` 负责组装模块；Java 里这两件事都由启动类上的注解 + 自动扫描完成。

### 3.2 多环境配置：一套代码，多套环境

| 文件                                                           | 干什么                                                     | Nest 对应                             |
| -------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------- |
| [application.yml](src/main/resources/application.yml)           | 公共配置（端口、MyBatis-Plus、接口文档、自定义 `app.*`） | `config/development.yml` 的公共部分 |
| [application-dev.yml](src/main/resources/application-dev.yml)   | 开发环境（本地 MySQL、Redis db 2、打印 SQL）               | 开发环境 yml                          |
| [application-prod.yml](src/main/resources/application-prod.yml) | 生产环境（`/prod-api`、环境变量注入账号密码）            | 生产环境 yml                          |

要点：

- `spring.profiles.active: dev` 就是“现在用哪套配置”，相当于 `NODE_ENV=development`。启动时也能临时换：`--spring.profiles.active=prod`。
- 接口前缀没写在每个 Controller 上，而是 `server.servlet.context-path: /dev-api` 统一加，相当于 Nest 的 `app.setGlobalPrefix('dev-api')`。
- 生产配置里 `${MYSQL_HOST:localhost}` 的意思是“优先读环境变量，没有就用默认值”，避免把密码写进代码库。
- `spring.jackson` 统一了日期格式和东八区，防止前端看到的时间差 8 小时。

### 3.3 配置绑定：yml 变成 Java 对象

文件：[AppProperties.java](src/main/java/com/sysnest/admin/config/properties/AppProperties.java)

```java
@Data
@ConfigurationProperties(prefix = "app")
public class AppProperties {
    private String admin = "admin";
    private Upload upload = new Upload();
    private Jwt jwt = new Jwt();

    @Data
    public static class Jwt {
        private String secret;
        private Duration accessTokenExpire = Duration.ofHours(2);
    }
}
```

大白话：

- yml 里写 `app.jwt.access-token-expire: 2h`，Java 里直接读 `appProperties.getJwt().getAccessTokenExpire()`，不用自己解析字符串。
- 名字会自动对应：`access-token-expire` ↔ `accessTokenExpire`（这叫松散绑定）。
- 嵌套类只是让配置看起来分层，不然一个类会堆几十个字段。

> Nest 对照：相当于 `AppConfigService` 读取 `development.yml` 后提供 `configService.jwt.accessTokenExpire`，区别是 Java 这边会自动转成对象和 `Duration` 类型。

## 4. 通用响应与异常处理

### 4.1 统一响应：所有接口长一个样

文件：[Result.java](src/main/java/com/sysnest/admin/common/api/Result.java)

```json
{ "code": 200, "msg": "success", "data": { } }
```

- 成功：`Result.ok(data)`
- 失败：`Result.fail(ErrorCode.USER_NOT_FOUND)`

> Nest 对照：Nest 端由 `TransformInterceptor` 自动把 Controller 的返回值包一层；Java 这边目前是 **Controller 手动返回 `Result`**，所以在每个接口方法里要写 `return Result.ok(...)`。效果一样，写法略有不同。

### 4.2 错误码：报错也有编号

文件：[ErrorCode.java](src/main/java/com/sysnest/admin/common/enums/ErrorCode.java)

按业务分段，和 Nest 端完全一致：

| 号段 | 管什么   | 举例                                      |
| ---- | -------- | ----------------------------------------- |
| 1xxx | 用户相关 | `USER_NOT_FOUND(1001)` 用户不存在       |
| 2xxx | 验证码   | `CAPTCHA_ERROR(2002)` 验证码错误        |
| 3xxx | Token    | `TOKEN_EXPIRED(3001)` Token 过期        |
| 4xxx | 权限     | `NO_PERMISSION(4001)` 没有权限          |
| 5xxx | 参数     | `PARAM_ERROR(5001)` 参数错误            |
| 6xxx | 配置     | `CONFIG_NOT_FOUND(6001)` 配置不存在     |
| 7xxx | 字典     | `DICT_TYPE_IN_USE(7004)` 字典类型被占用 |
| 8xxx | 定时任务 | `JOB_CRON_INVALID(8002)` cron 不合法    |
| 9xxx | 限流     | `RATE_LIMIT_EXCEEDED(9001)` 请求太频繁  |

> Nest 对照：就是 `common/enums/error-code.enum.ts` 的 Java 版，编号一致，前端不用改判断逻辑。

### 4.3 抛业务异常：出错了直接“扔”，不用层层 return

文件：[BusinessException.java](src/main/java/com/sysnest/admin/common/exception/BusinessException.java)

```java
throw new BusinessException(ErrorCode.USER_NOT_FOUND);
throw new BusinessException(ErrorCode.PARAM_ERROR, "用户名不能为空");
```

> Nest 对照：`throw new BusinessException('用户不存在', ErrorCodeEnum.USER_NOT_FOUND)`。

### 4.4 全局异常处理：所有异常最后都汇到这里

文件：[GlobalExceptionHandler.java](src/main/java/com/sysnest/admin/common/exception/GlobalExceptionHandler.java)

用 `@RestControllerAdvice` 挂一个“总捕头”，各种异常自动转成统一 JSON：

| 异常类型（什么情况）                                  | 返回什么                           |
| ----------------------------------------------------- | ---------------------------------- |
| `BusinessException`（自己抛的业务错）               | 原样返回错误码和提示，日志记 warn  |
| `MethodArgumentNotValidException`（请求体校验失败） | HTTP 400 + `BAD_REQUEST(400)` + 第一条校验提示 |
| `BindException`（查询参数绑定失败）                 | 同上                               |
| `ConstraintViolationException`（方法参数校验失败）  | HTTP 400 + `BAD_REQUEST(400)`      |
| `HttpMessageNotReadableException`（JSON 格式错误）  | HTTP 400 + `BAD_REQUEST(400)`      |
| `AccessDeniedException`（@PreAuthorize 没通过）     | `NO_PERMISSION`                  |
| 其它所有 `Exception`                                | `INTERNAL_ERROR`，日志打完整堆栈 |

所以业务代码只负责“抛”，不用写 try-catch 拼返回值。

> Nest 对照：等于把 `business-exception.filter.ts` 和 `http-exception.filter.ts` 合并成一个类。

### 4.5 参数校验：前端传错，后端先拦

引入 `spring-boot-starter-validation` 后，直接在 DTO 字段上贴标签：

```java
@Data
public class UserQuery extends PageQuery {
    @NotBlank(message = "用户名不能为空")
    private String username;
}
```

三种触发场景都已覆盖：

- `@RequestBody + @Valid`：请求体校验（对应 Nest 的 `@Body() + class-validator`）。
- 查询参数直接绑定对象：绑定失败抛 `BindException`。
- 类上 `@Validated` + 方法参数注解：方法级校验。

> 与 Nest 的一个区别：Nest 的 `ValidationPipe({ whitelist: true })` 会自动把 DTO 里没声明的字段剔掉；Spring 默认不会自动“白名单剔除”，如需要可自行加过滤器（新手先知道有这个差异即可）。

### 4.6 分页：页码 + 每页条数

文件：[PageQuery.java](src/main/java/com/sysnest/admin/common/api/PageQuery.java)、[PageResult.java](src/main/java/com/sysnest/admin/common/api/PageResult.java)

```java
public class UserQuery extends PageQuery { }   // 自带 pageNum=1、pageSize=10

Page<User> page = userMapper.selectPage(query.toPage(), wrapper);
return Result.ok(PageResult.of(page));         // { list, total, page, pageSize }
```

- `pageSize` 最大 500，防止有人一次拉全表。
- 返回结构已与 Nest 对齐：`{ list, total, page, pageSize }`，其中 `page`、`pageSize` 直接取自分页对象。

> Nest 对照：`pagination.dto.ts` + `PaginationVo`。

## 5. 持久层：MyBatis-Plus（操作数据库）

### 5.1 公共实体：每张表都有的字段，抽出来

文件：[BaseEntity.java](src/main/java/com/sysnest/admin/common/entity/BaseEntity.java)

```java
@Data
public abstract class BaseEntity implements Serializable {
    @TableId(type = IdType.AUTO)                    // 主键，数据库自增
    private Integer id;

    @TableLogic                                     // 逻辑删除标记
    private String deleteStatus;

    @TableField(fill = FieldFill.INSERT)            // 新增时自动填
    private String createdBy;

    @TableField(fill = FieldFill.INSERT_UPDATE)     // 新增和修改都自动填
    private LocalDateTime updatedAt;
}
```

大白话：

- 每张表都有 id、删除标记、创建人、创建时间这些“通用字段”，没必要在每个实体里抄一遍，所以抽到父类。
- `@TableId(type = IdType.AUTO)`：主键交给数据库自增，相当于 TypeORM 的 `@PrimaryGeneratedColumn()`。
- `@TableLogic`：逻辑删除。调用删除时不会真删数据，而是执行 `update ... set deleteStatus = '1'`；平时查询会自动带上 `deleteStatus = '0'`，相当于 Nest 端 Repository 里手动拼软删除条件，这边由框架代劳。
- `@TableField(fill = ...)`：声明这个字段由“自动填充器”负责，不用手写。

> Nest 对照：`common/entities/base.entity.ts`。

### 5.2 全局配置：一次配好，所有表生效

`application.yml`：

```yaml
mybatis-plus:
  mapper-locations: classpath*:/mapper/**/*.xml   # XML 写复杂 SQL 的位置
  type-aliases-package: com.sysnest.admin.modules  # 实体别名包
  configuration:
    map-underscore-to-camel-case: true             # 下划线转驼峰
  global-config:
    db-config:
      id-type: auto                                # 主键自增
      logic-delete-field: deleteStatus             # 逻辑删除字段
      logic-delete-value: '1'                      # 已删除
      logic-not-delete-value: '0'                  # 未删除
```

- 数据库列叫 `receiver_id`，实体里写 `receiverId`，靠 `map-underscore-to-camel-case` 自动对上。
- 简单增删改查用代码里的 `LambdaQueryWrapper` 拼条件；复杂 SQL 写进 `resources/mapper/**/*.xml`。

> Nest 对照：相当于 TypeORM 的全局连接配置 + 命名策略配置。

### 5.3 分页插件：不装它，分页是假的

文件：[MybatisPlusConfig.java](src/main/java/com/sysnest/admin/config/MybatisPlusConfig.java)

```java

```

没有这个插件，`selectPage` 可能把全表查回内存再切页，数据一多就出问题。

### 5.4 公共字段自动填充：少写重复代码

文件：[MybatisMetaObjectHandler.java](src/main/java/com/sysnest/admin/config/MybatisMetaObjectHandler.java)

```java
// 新增时
strictInsertFill(metaObject, "createdAt", LocalDateTime.class, now);
strictInsertFill(metaObject, "createdBy", String.class, SecurityUtils.currentUsername());
strictInsertFill(metaObject, "deleteStatus", String.class, "0");

// 修改时

```

- 新增：自动写创建时间、创建人，默认“未删除、启用”。
- 修改：自动更新修改时间和修改人。
- 当前操作人来自登录信息；定时任务等没有登录态的场景会写成 `system`。

### 5.5 以后写业务模块的样子（模板）

```java
// entity：一张表对应一个类
@Data
@EqualsAndHashCode(callSuper = true)
@TableName("sys_user")
public class User extends BaseEntity {
    private String username;
    private String nickname;
}

// mapper：继承 BaseMapper 就自带增删改查
public interface UserMapper extends BaseMapper<User> { }

// service
@Service
@RequiredArgsConstructor
public class UserService {
    private final UserMapper userMapper;

    public UserVo findById(Integer id) {
        User user = userMapper.selectById(id);
        if (user == null) {
            throw new BusinessException(ErrorCode.USER_NOT_FOUND);
        }
        return new UserVo(user);
    }
}
```

> Nest 对照：`user.entity.ts` + `user.repository.ts` + `user.service.ts`。Java 把 Repository 简化成 `BaseMapper`，常规 CRUD 不用自己写 SQL。

## 6. Spring Security + JWT（登录和权限）

### 6.1 请求进来后的完整路线

```text
浏览器请求
  → 跨域处理（WebMvcConfig，相当于 enableCors）
  → JWT 过滤器（JwtAuthenticationFilter，相当于 jwt-auth.guard）
       ├─ 带了合法 Token：把用户信息放进“当前上下文”
       └─ 没带/过期：先放行到下一步，由安全配置决定 401
  → 安全过滤链（SecurityConfig，相当于全局 Guard）
       ├─ 白名单路径：直接放行（登录、验证码、文档、上传文件等）
       └─ 其它路径：必须登录
  → 方法级权限（@PreAuthorize + PermissionChecker，相当于 permission.guard）
  → Controller → Service → Mapper → 数据库
```

### 6.2 安全配置：哪些能进，哪些要登录

文件：[SecurityConfig.java](src/main/java/com/sysnest/admin/security/SecurityConfig.java)

```java
http.csrf(AbstractHttpConfigurer::disable)
    .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
    .authorizeHttpRequests(auth -> auth
        .requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()
        .requestMatchers(whitelist).permitAll()
        .anyRequest().authenticated())
    .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
```

大白话：

- `csrf` 关掉：前后端分离 + Token 放在请求头，不怕传统表单 CSRF。
- `STATELESS`：服务器不记 Session，每次请求靠 Token 自证身份，容易扩容（多台机器不用共享 Session）。
- `whitelist`：白名单，写在 `app.security.whitelist`，**注意是相对 `/dev-api` 的路径**。例如真实地址 `/dev-api/auth/login`，这里写 `/auth/login`。
- 其余请求都要登录，没登录由入口点统一返回 401。

> Nest 对照：`main.ts` 里 `app.useGlobalGuards(new JwtAuthGuard(), new PermissionGuard(...))`，白名单则在 `jwt-auth.guard.ts` 里用 `configService` 判断。

### 6.3 JWT 双 Token：一个短的用来访问，一个长的用来续期

文件：[JwtTokenProvider.java](src/main/java/com/sysnest/admin/security/JwtTokenProvider.java)

- Access Token（默认 2 小时）：每次请求带它。
- Refresh Token（默认 7 天）：Access 过期后，用它换新的 Access，避免重新登录。
- 两个 Token 用**不同密钥**，互相不能冒用。
- Token 里存了：用户名、用户 ID、权限点数组。

JJWT 0.12 的写法和老教程不一样（学习时注意别抄旧代码）：

```java
// 生成
Jwts.builder().subject(username).claim("userId", id)
    .issuedAt(now).expiration(exp).signWith(secretKey).compact();

// 解析
Jwts.parser().verifyWith(secretKey).build()
    .parseSignedClaims(token).getPayload();
```

- HS256 算法要求密钥至少 32 字节，太短启动直接报错，反而能早点发现配置问题。

> Nest 对照：`auth.service.ts` 里签发 Token + `strategies/jwt.strategy.ts` 里校验 Token。Java 把这两块合在 `JwtTokenProvider` 和过滤器里。

### 6.4 当前登录用户：随用随取

文件：[LoginUser.java](src/main/java/com/sysnest/admin/security/LoginUser.java)、[SecurityUtils.java](src/main/java/com/sysnest/admin/security/SecurityUtils.java)

```java
Integer userId = SecurityUtils.currentUserId();
String username = SecurityUtils.currentUsername();
```

> Nest 对照：`@User() user: UserInfo` 装饰器 + `req.userInfo`。Java 没有装饰器，用工具类从“安全上下文”里取。

### 6.5 权限点：`system:user:list` 这种字符串说了算

文件：[PermissionChecker.java](src/main/java/com/sysnest/admin/security/PermissionChecker.java)

在 Controller 方法上这样写：

```java
@PreAuthorize("@perm.has('system:user:list')")
@GetMapping("/page")
public Result<PageResult<UserVo>> page(UserQuery query) { ... }
```

规则：

- 用户是超级管理员（`app.admin`，默认 admin）：直接放行。
- 权限点里有通配符 `*:*:*`：直接放行。
- 否则必须精确命中。

> Nest 对照：`@Permission('system:user:list')` + `permission.guard.ts`。Java 用 Spring Security 的 `@PreAuthorize` + 一个名为 `perm` 的 Bean，效果相同。

### 6.6 401 / 403：过滤器里也要返回统一 JSON

文件：[RestAuthenticationEntryPoint.java](src/main/java/com/sysnest/admin/security/RestAuthenticationEntryPoint.java)、[RestAccessDeniedHandler.java](src/main/java/com/sysnest/admin/security/RestAccessDeniedHandler.java)

为什么要单独写？因为请求在进入 Controller 之前就被 Security 拦下了，进不了全局异常处理器。

- 401：没登录 / Token 无效。
- 403：登录了但没权限。

由 `SecurityResponseWriter` 手动写出 `{ code, msg, data }` 和 HTTP 状态码。

> Nest 对照：Guard 里抛 `UnauthorizedException` / `ForbiddenException`，再由全局过滤器转成统一格式。

### 6.7 密码加密

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

登录校验时用 `passwordEncoder.matches(明文, 数据库里的密文)`。

> Nest 对照：`bcrypt` 包的 `compare()`，两边密文格式兼容。

### 6.8 Token 黑名单：登出后旧 Token 立即作废

JWT 签发后本身无法“撤回”，所以用 Redis 记一笔“这个 Token 已作废”：

- 登出或强制下线时调用：`tokenBlacklistService.blacklist(token)`；
- 实际键：`java:token:blacklist:<完整 Token>`（前缀来自缓存工具）；
- 过期时间：取该 Token 的剩余有效期，到期自动从 Redis 消失，不会越积越多；
- 每次请求：`JwtAuthenticationFilter` 解析 Token 前先查黑名单，命中就清空登录态，最终返回 401。

> Nest 对照：`redisKeys.tokenBlacklist.prefix = 'token:blacklist:'` + Guard 里的黑名单判断；Java 拆成 `TokenBlacklistService` 负责写入、过滤器负责拦截。

### 6.9 认证接口与登录流程

文件：[AuthController.java](src/main/java/com/sysnest/admin/modules/auth/controller/AuthController.java)、[AuthService.java](src/main/java/com/sysnest/admin/modules/auth/service/AuthService.java)

| 接口 | 说明 |
| --- | --- |
| `POST /auth/login` | 登录，返回 `{ accessToken, refreshToken }` |
| `GET /auth/userInfo` | 当前用户信息（id、昵称、头像、角色、权限点） |
| `POST /auth/refresh` | 用 refreshToken 换新的双 Token |
| `POST /auth/logout` | Token 拉黑 + 移除在线记录 + 清用户缓存 |
| `GET /auth/getRouters` | 动态路由树 |

登录顺序（与 Nest 严格一致）：

1. 锁定检查 `login:lock:{username}`，锁定期间直接拒绝；
2. 验证码开关开启时校验验证码；
3. 按用户名查用户（`@TableLogic` 自动过滤已删除）；
4. BCrypt 校验密码，错误则 `login:retry:{username}` +1，达到上限写锁定键；
5. 检查 `status='0'`（禁用）；
6. 成功：清失败计数 → 生成双 Token → 写 `user:info:{userId}` 缓存、`online:token:{token}` 在线记录、登录日志。

> Nest 对照：`auth.service.ts` 的 `login/refresh/logout/getUserInfo/getRouters`；Java 把权限缓存拆到 `AuthCacheService`，在线记录拆到 `OnlineUserService`。

### 6.10 验证码

文件：[CaptchaService.java](src/main/java/com/sysnest/admin/modules/captcha/service/CaptchaService.java)

- `GET /captcha` 返回 `{ key, image }`，`image` 是完整 SVG 字符串，前端可直接 `v-html`；
- 4 位字符，去掉容易混淆的 `0/o/1/i`，带干扰线和噪点；
- 答案以小写存入 `captcha:{key}`，TTL 300 秒；
- 校验时先取出再删除，验证码只能用一次，比较不区分大小写；
- 开关读 `sys_config` 的 `sys.login.captchaEnabled`，只有值严格等于 `false` 才关闭（初始数据就是 false）；
- 接口加 `@RateLimit`，60 秒同一 IP 最多 10 次。

> Nest 对照：`captcha.service.ts` 使用 `svg-captcha`；Java 用字符串拼 SVG，避免额外图形库依赖。

## 7. Redis（缓存）

文件：[RedisConfig.java](src/main/java/com/sysnest/admin/config/RedisConfig.java)

```java
template.setKeySerializer(new StringRedisSerializer());                  // 键按普通字符串存
template.setValueSerializer(new GenericJackson2JsonRedisSerializer());   // 值按 JSON 存
```

- Key 用字符串：打开 `redis-cli` 能直接看懂键名，排查方便。
- Value 用 JSON：Nest 和 Java 两个后端都能读同一份缓存，不挑语言。
- 环境隔离：Nest 用 db 1，Java 用 db 2，互不覆盖。

> Nest 对照：`core/redis/redis.service.ts` 封装的方法。

### 7.1 通用缓存工具：RedisUtils

文件：[RedisUtils.java](src/main/java/com/sysnest/admin/common/util/RedisUtils.java)

业务代码只写“业务 key”，统一前缀由工具类自动拼：

```java
redisUtils.set("captcha:abc123", "8888", Duration.ofMinutes(5)); // 实际键：java:captcha:abc123
String code = redisUtils.get("captcha:abc123");
long ttl = redisUtils.getExpire("captcha:abc123");               // 秒；-1 永久，-2 不存在
Set<String> keys = redisUtils.scan("captcha:*");                 // 返回去掉前缀的业务 key
redisUtils.delete("captcha:abc123");
```

- 前缀来自 `app.redis.key-prefix`，默认 `java:`，与 Nest 端（db 1）彻底隔离；
- `scan` 用游标分批遍历，不用 `KEYS *`，不会阻塞 Redis；
- 后续 Token 黑名单、字典缓存、在线用户都复用它，不再各自拼前缀。

> Nest 对照：相当于 `redis.service.ts` 里的 `get/set/del/ttl/keys`，只是把前缀统一收口了。

### 7.2 限流：Redis + Lua 三层原子计数

文件：[RateLimiterService.java](src/main/java/com/sysnest/admin/common/service/RateLimiterService.java)、[RateLimitInterceptor.java](src/main/java/com/sysnest/admin/common/interceptor/RateLimitInterceptor.java)、[IpUtils.java](src/main/java/com/sysnest/admin/common/util/IpUtils.java)

每个请求依次检查三层，任意一层超限就返回 `9001`：

| 层 | 业务键（实际自动加 `java:` 前缀） | 配置 |
| --- | --- | --- |
| 全局 | `rate_limit:global` | `app.rate-limit.global` |
| 单 IP | `rate_limit:ip:{ip}` | `app.rate-limit.ip` |
| 用户 / 接口 | 已登录 `rate_limit:user:{userId}:{METHOD}:{path}`；未登录降级为 `rate_limit:default:{ip}:{METHOD}:{path}` | `app.rate-limit.default-rule` |

- 计数逻辑写在 Lua 脚本里：`INCR` → 首次 `EXPIRE` → 超过阈值返回 0，由 Redis 单线程原子执行；
- IP 优先从 `X-Forwarded-For` / `X-Real-IP` 取，适配 Nginx 反向代理；
- 静态资源与 Swagger 不做限流，避免页面刷新被误伤；
- Redis 返回异常时保守放行，防止缓存故障导致全站不可用。

- 方法上 `@RateLimit(time, count, dimension)` 可覆盖默认规则；登录、刷新、验证码已按“60 秒 / 10 次 / IP”限制；
- 顶层 `rate_limit:global`、`rate_limit:ip:{ip}` 始终先检查，任何接口都逃不掉。

> Nest 对照：`rateLimit.global` / `rateLimit.ip` / `rateLimit.default`；Java 的 `default` 因是关键字改叫 `default-rule`，用户维度按登录态自动选择。

### 7.3 操作日志与登录日志

文件：[OperLogAspect.java](src/main/java/com/sysnest/admin/modules/log/aspect/OperLogAspect.java)、[LoginLogService.java](src/main/java/com/sysnest/admin/modules/log/service/LoginLogService.java)

> Nest 对照：`@Log()` + `logging.interceptor.ts`、`login-log.service.ts`、`access-log.middleware.ts`。

- 站内信：`/system/message`，定向或全员发送时每个接收人一条记录；
- 收件箱、未读数、详情、已读、删除全部强制 `receiverId = 当前用户`，操作他人消息按“不存在”处理；
- 已读同时写 `readAt`；发送成功后通过 SSE 给每个接收人推送 `{"count": 接收人数}`。

### 10.5 定时任务与调度日志

文件：`modules/job/service/JobService.java`、`JobLogService.java`、`SampleTask.java`

- **动态调度**：`DynamicTaskScheduler` 内部是 Spring 的 `ThreadPoolTaskScheduler`，`Map<任务ID, ScheduledFuture>` 保存每个任务。新增/修改/启用时 `schedule()` 会先 `cancel()` 旧任务再注册，删除/暂停时直接 `cancel()`；
- **启动恢复**：`JobService` 实现 `ApplicationRunner`，应用启动完成后查出 `status=0` 的任务逐个注册，相当于 Nest 的 `OnModuleInit`；
- **cron**：Spring 的 `CronExpression` 是“秒 分 时 日 月 周”六段；Nest 端兼容 Quartz 的 `?`，Java 端统一把 `?` 换成 `*` 再解析。非法表达式返回 `JOB_CRON_INVALID(8002)`，合法时用 `CronExpression.next()` 算 `nextValidTime`；
- **调用目标**：`beanName.method(args)` 用正则拆开，`ApplicationContext.getBean(beanName)` 拿对象，再用反射调方法。参数支持字符串、整数、小数、布尔值；Bean 不存在返回 8003，方法不存在返回 8004；
- **并发/补偿策略**：`runningJobs` 记录正在执行的任务 ID，`concurrent=1` 时定时触发会跳过；手动执行不限制。`misfirePolicy=1` 注册后立即跑一次，`=2` 立即跑一次后取消调度，`=3` 正常按 cron 跑；
- **调度日志**：每次执行（含手动）都往 `sys_job_log` 写一条，成功/失败、日志信息、异常堆栈都会落库；日志表没有软删除字段，所以 `SysJobLog` 不继承 `BaseEntity`。

> Nest 对照：`cron-schedule.service.ts`（CronJob Map）+ `job.service.ts`（ModuleRef 取 Bean）；Java 对应 `DynamicTaskScheduler` + `ApplicationContext`。

### 10.6 缓存监控与缓存列表

文件：`modules/cache/service/CacheService.java`

- **Redis INFO**：通过 `RedisTemplate.execute(...)` 拿到底层 `RedisConnection`，再调用 `serverCommands().info("server"/"memory"/...)` 按分组读取，`dbSize()` 取当前库 key 数，`info("commandstats")` 里的 `calls=` 解析成饼图数据；
- **不阻塞 Redis**：列 key 一律用 `SCAN`（`RedisUtils.scan`），不用 `KEYS *`；
- **缓存分组**：后端按业务前缀把缓存分成 6 组（用户信息、验证码、Token 黑名单、字典、参数配置、在线用户）。实际 Redis key 带 `java:` 前缀，接口返回时展示业务 key，查看/删除时再自动补回前缀；
- **按类型读值**：先取 `type` 和 `ttl`，再分别用 string/list/hash/set/zset 的命令读取；复杂类型用 Jackson 转成 JSON 字符串给前端；
- **字符串去引号**：Java 的 JSON 序列化会把 `"false"` 连同引号存进 Redis，展示时如果发现是 JSON 字符串就还原成 `false`，和 Nest 端的纯文本效果一致；
- 清缓存接口都会记录操作日志，权限是 `monitor:cache:list` / `monitor:cache:remove`。

> Nest 对照：`cache.service.ts`。

### 10.7 在线用户与服务监控

文件：`modules/online/service/OnlineUserService.java`、`modules/server/service/ServerService.java`

- **在线用户数据**：登录和刷新 Token 时写 `online:token:{accessToken}`，值是在线用户对象，TTL 等于 Access Token 剩余有效期，过期自动消失；
- **在线列表**：`SCAN online:token:*` 取出所有记录，按用户名/IP 模糊筛选，再按 `loginTime` 倒序；
- **强退**：把该 token 加入黑名单（`token:blacklist:{token}`）并删除在线记录，对方下次请求会被 JWT 过滤器拦下返回 401；
- **小细节**：JWT 的 `iat` 只精确到秒，同一秒内连续登录两次会生成完全相同的 token，在线记录也会是同一条；Nest 端行为相同；
- **服务监控**：不引入 OSHI，直接用 JDK 自带能力：
  - `com.sun.management.OperatingSystemMXBean` 取 CPU 使用率、总内存/空闲内存；
  - `Runtime` 取 JVM 堆内存；
  - `File.listRoots()` 取磁盘；
  - `NetworkInterface` 取本机非回环 IPv4；
  - `RuntimeMXBean` 取运行时长，`SpringBootVersion` 取框架版本；
- 前端字段原本是给 Node 设计的（`node`、`jvm`），Java 端两个字段都填 JVM 信息，避免改前端。

> Nest 对照：`online.service.ts`、`server.service.ts`（systeminformation）。

### 10.8 文件日志查询

文件：`modules/filelog/service/FileLogService.java`、`common/logging/AccessLogFilter.java`

- **目录**：`logs/access`、`logs/app`、`logs/error`，根目录统一读取 `app.file-log.dir`，logback 用 `<springProperty>` 读同一个配置；
- **访问日志结构化**：`AccessLogFilter` 把方法、路径、状态码、IP、操作人、耗时、UA 组成 JSON 写进日志正文；日志查询接口再把 JSON 解析成前端要的字段；
- **操作人怎么拿到**：AccessLogFilter 在 Spring Security 过滤链外面，安全上下文已经被清理，所以 `JwtAuthenticationFilter` 认证成功时会把用户名放进 `request` 属性 `AUTH_USERNAME`，访问日志从这里取；
- **解析日志行**：用正则拆出时间、级别、线程、Logger、正文；异常堆栈等续行会追加到上一条日志的 `stack`；访问日志正文如果是 JSON，再解析出 method/url/status/ip/user/cost/ua；
- **文件名校验**：白名单同时兼容 Java logback（`access.log`、`access.2026-11-22.0.log`）和 Nest 端（`access-20261122-0001.log`），并做 `Path.normalize()` 与根目录前缀校验，防止路径穿越；
- **扫描上限**：内容查询最多扫 20 个文件、20 万行；原始预览最多读 50 万行，超出时返回 `truncated=true`；
- 接口权限：列表 `monitor:fileLog:list`，内容/预览 `monitor:fileLog:query`，下载 `monitor:fileLog:download`，删除 `monitor:fileLog:remove`。

> Nest 对照：`file-log.service.ts`（解析 JSON 行）+ `file-logger.service.ts`（写文件）。

### 10.9 操作日志与登录日志（查询侧）

文件：`modules/log/service/OperLogService.java`、`LoginLogService.java`

- **写入和查询分开**：写入仍由 `OperLogAspect`（操作日志）和 `LoginLogService.record()`（登录日志）负责，查询侧只读数据库；
- **操作日志查询**：支持模块标题、操作人、业务类型、状态、请求方式、时间范围，按 id 倒序分页；
- **物理删除**：日志表在 Nest 端是直接 `DELETE`，所以 `SysOperLogMapper` 额外写了 `@Delete` 方法，不继承 `BaseEntity` 的软删除行为；这样“清空”后数据库是真的空了，不会越积越多；
- **登录日志查询**：支持账号、IP、状态、时间范围；`sys_logininfor` 本身没有 `deleteStatus`，直接 `deleteByIds` / `delete(null)` 即可；
- 操作日志的删除/清空本身也会被 `@OperLog` 记录，所以删除后总数可能“删一条、加一条”，这是正常现象。

> Nest 对照：`log.service.ts`、`login-log.service.ts`。

## 13. 常见问题（新手最容易踩的坑）

| 现象                                         | 原因                                | 怎么办                                               |
| -------------------------------------------- | ----------------------------------- | ---------------------------------------------------- |
| 启动日志提示 `No MyBatis mapper was found` | 业务 Mapper 还没写                  | 正常现象，等 `modules/*/mapper` 有接口后自动消失   |
| Swagger 打不开                               | 路径忘了带 `/dev-api`             | 用 `http://localhost:3100/dev-api/swagger-ui.html` |
| 401 但 Token 明明是对的                      | 路径被拦了，或密钥不一致            | 检查白名单配置、`app.jwt.secret`                   |
| 端口被占用                                   | 3100 被另一个后端占了              | 两套后端二选一启动，或加 `--server.port=xxxx`    |
| 时间差 8 小时                                | 时区没生效                          | 确认 `spring.jackson.time-zone: GMT+8`             |
| Redis 读出来乱码                             | 序列化方式不一致                    | Key 用 String、Value 用 JSON，和 Nest 端约定保持一致 |
| 上传图片 404                                 | 路径少写了 `/dev-api`             | Java 版访问 `/dev-api/uploads/xxx`                 |
| 校验注解不生效                               | 忘了加 `@Valid` 或 `@Validated` | 请求体加 `@Valid`，方法参数加 `@Validated`       |
